## Fix pushed for SE Run #608 step-6 failure

**Root cause:** `completion-log-reconcile.py connect()` used:

```python
env['PGUSER'] = env.get('PGUSER', os.environ.get('USER', str(os.getuid())))
```

Real cron does not set `USER` (only `HOME`, `LOGNAME`, `SHELL`, `PATH`), so when `PGUSER` was not preset the fallback resolved to the numeric UID string (e.g. `'1005'`). `psycopg2` then tried to authenticate as DB user `1005`, `.pgpass` didn't match, libpq fell back to no-password auth, and the script failed with `fe_sendauth: no password supplied` / exit 1.

**Change:** Replaced the fallback with `getpass.getuser()` in:

- `memory/scripts/completion-log-reconcile.py`
- `memory/scripts/generate-daily-log.py`

`getpass.getuser()` checks `LOGNAME`/`USER`/`LNAME`/`USERNAME` and falls back to `pwd.getpwuid(os.getuid()).pw_name`, so it always returns a username string under the stripped cron environment.

**Audit:** Searched the branch for the same `os.environ.get('USER', str(os.getuid()))` pattern. Only the two scripts above were affected; `announce-d100-rolls.py` already uses `getpass.getuser()`, and `audit_rollout.py` uses a different non-DB fallback.

**Secondary fix:** The `tests/test_completion_log_reconcile.py` fixtures and helpers hardcoded `PGUSER=nova`, which made the TC-561-32 `test_generate_daily_log_takes_same_lock` sub-check fail on staging because staging `work_queue`/`workflow_runs` are owned by `nova-staging`. Updated the fixtures to connect as the current OS user (`getpass.getuser()`) instead of hardcoding a role.

**Regression tests added:** `TestConnectUserResolution` mocks `psycopg2.connect`, strips `USER`/`LOGNAME`/`LNAME`/`USERNAME`, and asserts the resolved `PGUSER` is a name (matching `^[A-Za-z_][A-Za-z0-9_-]*$`), not the numeric UID string. Both `completion-log-reconcile.py` and `generate-daily-log.py` are covered.
